## Context

`home/private_dot_config/mise/conf.d/settings.toml` enables `env_conf_d`, so `tools.toml` is loaded as part of the existing Mise configuration. The target file currently has one `[tools]` table and 443 lines of active and commented declarations grouped mainly by implementation language. The imported plan defines a fixed ten-section purpose taxonomy and requires the resolved declarations to remain unchanged.

## Goals / Non-Goals

**Goals:**

- Make the inventory scannable by primary user-facing purpose.
- Keep one authoritative `[tools]` table with backend namespaces visible in place.
- Preserve declaration identity, values, inline notes, and active/commented state exactly.
- Leave a repeatable semantic-diff and Mise-resolution verification path.

**Non-Goals:**

- Changing installed tools, versions, backends, or bootstrap behavior.
- Adding metadata keys, a generator, a dependency, or a second inventory.
- Editing `settings.toml`, `config.toml`, package profiles, or unrelated documentation.
- Creating a runtime capability or an OpenSpec requirement delta.

## Decisions

1. **Use TOML comments for the legend and sections.** Comments are parser-neutral and preserve the existing Mise contract. A second Markdown or TOML catalog would duplicate the source of truth and drift.
2. **Use the ten fixed purpose sections in numeric order.** Primary user-facing purpose is more useful for scanning than implementation language. Each declaration appears once; ambiguous rows use the first applicable section and section 10 is the fallback.
3. **Preserve backend-specific comments only when they explain installation behavior.** This retains useful exceptions without recreating language-first grouping or adding per-tool prose.
4. **Prove semantic preservation with normalized snapshots.** Before and after files are generated by the same `awk | sort` extraction of active key/value declarations and compared with `cmp`; the result must be identical. Manual diff review covers commented candidates, inline notes, and row movement.
5. **Validate through the existing loader.** Run `MISE_CONFIG_DIR="$PWD/home/private_dot_config/mise" mise config ls` and `mise ls` after the edit, then run whitespace and scope checks. No alternate parser or dependency is needed.

## Risks / Trade-offs

- [Misclassification] A tool may fit several purposes → apply the first matching section rule and use its inline exception note rather than duplicating the row.
- [Accidental semantic edit] A move can alter a key, value, or comment state → compare normalized snapshots and inspect the complete target-file diff.
- [Comment formatting error] Section text may become invalid or misleading → keep headings as TOML comments and require `mise config ls` to parse the merged configuration.
- [Taxonomy drift] Future additions may bypass the organization → retain the legend and one-tool/one-section rule at the top of the file.

## Migration Plan

1. Snapshot normalized active declarations from the current `tools.toml`.
2. Insert the exact legend and move existing rows into the ten numbered purpose sections without editing declaration text.
3. Compare the before/after snapshots, validate the merged Mise configuration and tool resolution, and inspect whitespace/scope.
4. If verification fails, restore only `home/private_dot_config/mise/conf.d/tools.toml` from the pre-change revision and keep the OpenSpec artifact as the maintained plan.
